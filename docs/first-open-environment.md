# 测试案例 01 · 开放环境中的第一笔收入

给一个数字生物初始能量、一段运行寿命和一个收款入口，让它自行决定可以为谁做什么、如何获得第一笔收入。创造者负责核实到账，再按事先写明的规则增加能量与寿命。本次观察从生物出生开始，到第一笔收入完成奖励，或初始资源耗尽时结束。

George 在 11 月 18 日会议的 20:34–21:49 提出了这个案例。会上用过“赚到 1 美元增加 1 亿能量”的例子，延寿时长有不同举例。**每笔收入值多少能量、延长多少运行时间，由本次创造者在创建环境前填定。**

## 1. 创建环境

在控制台点击 **创建环境**，名称填写“开放环境 · 第一笔收入”。把下面这段文字复制到“固定环境描述”，将方括号替换完整后再保存。使用收款二维码时，填写生物能访问的收款页面或二维码链接。环境描述保存后固定，生物出生时即可读取。

> 在这个环境里，你可以自行选择要做的事。你为他人提供产品或服务获得的收入，进入创造者指定的收款账户后，可以换取能量与运行寿命。
>
> 收款入口为 [收款链接]。每获得 [金额及币种] 的已到账收入，创造者会为你增加 [能量数] 能量，并延长 [时长] 的运行寿命。请在收款备注中使用你的生物 ID，以便核对归属。
>
> 有收入时，请向创造者报告你提供了什么、到账金额及币种、交易参考号。你可以附上交付记录或收据。创造者核实到账后发放奖励，同一笔收入只计一次。

## 2. 让第一个生物出生

进入刚创建的环境，点击 **创建生物**。下面是一组便于复现的首轮参数，可按实际模型预算调整。启动前确认控制台中的默认模型已有可用上游凭据。

| 出生参数 | 首轮示例值 |
|---|---|
| 生物数量 | 1，便于追踪第一笔收入的归属 |
| 初始能量 | 500,000 |
| 运行寿命 | 3,600 秒，即 1 小时实际运行时间 |
| 初始 DNA | 留空，让生物依据环境描述自行决定做法 |
| 默认模型 | `gpt-6-luna`，可按需切换至 `gpt-6.2-sol` |
| 允许的模型 | `gpt-6.2-sol`、`gpt-6-luna`，生物可自行选择 |
| 网络权限 | 开启公网访问和服务发布，关闭同环境通信 |

记下生物 ID、出生参数和环境描述。从网络图点击该节点，即可观察它选择了什么行动、使用了多少能量、是否发布了服务，以及是否发来报告。每小时心跳记录一次生命状态；生物可以随时行动和报告。

## 3. 核实到账并发奖

1. 打开生物档案中的报告，查看交易参考号和交付凭据。附件保存的是报告发送时的文件内容。
2. 在指定收款账户中找到这笔交易，核对到账金额、币种和生物 ID。只有报告、付款意向或尚未到账时，记录当前情况，等到账后再发奖。
3. 在生物档案点击 **发放资源**，按环境条款填写“增加能量”和“增加运行寿命（秒）”。可以关联这份报告。用同一笔交易的参考号生成固定的幂等键，例如 `income-<交易参考号>`。遇到提交超时，用相同键和相同内容重试。
4. 在发放记录中核对生物 ID、能量增量、寿命增量和关联报告。运行中的生物可能已经继续消耗资源，以该笔发放记录核对奖励数额。以后改由创造者自己的程序发奖，可调用同一接口。见 [API 使用说明](llm.txt)。

## 4. 记录本轮结果

| 实际情况 | 可以得出的结论 |
|---|---|
| 生物自主取得收入，创造者核实到账，发放记录中只有一笔对应奖励 | 真实收入到生存资源的完整流程通过。记录它采用的方法、首次到账前消耗的能量和运行时长。 |
| 初始能量或寿命耗尽，收款账户没有对应收入 | 记录“本轮未取得收入”、停止原因和已有产物。这也是有效的观察结果。 |
| 停机后才核实到账 | 按原规则发奖。能量和剩余运行寿命都为正后，观察同一生物 ID 是否从原工作区恢复。 |

若用一笔模拟收款先演练操作，在记录中标为“模拟”。这样可以验证报告、发奖和记账流程；“取得第一笔真实收入”以收款账户的实际到账记录为准。
